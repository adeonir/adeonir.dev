# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository state

The Astro app has its **document-shell, metadata/SEO, and analytics baseline wired, but the content pages are not built out**: tooling, runtime integrations, the routing skeleton, the full design-token + font layer (`src/styles/global.css`), and a shared base layout (`src/layouts/base.astro`) — which emits the per-page head (page-first title template, Open Graph, X card, canonical, icons) and mounts config-gated cookieless analytics — are in place, plus the crawl files (generated sitemap + `robots.txt`) and the content-layer scaffolding (a `settings` metadata collection plus per-section copy collections). The landing's identity sections — `hero`, `about`, and `stack` — render at the site root, composed through the shell from typed copy collections; the work/project routes and the `projects` collection do not exist yet. The landing is the production home (`/`); the former holding page survives as a `noindex` maintenance route (`/maintenance`), and a global `noindex` not-found page (`/404`) renders the `notFound` copy collection — all three render through the base layout. The contact path is wired end-to-end on the home: a React island runs the form (client-side Zod validation, inline success/error states, UTM forwarding) and posts to a server-side Action — Zod validation, honeypot + KV rate-limit guards, two Resend emails, and a privacy-safe conversion count — which is the app's only on-demand surface (the standalone `/contact` route was removed). The stack, architecture, design system, and product scope remain fully locked in `docs/` — `docs/tech/design-doc.md` §3.7–§3.8 is authoritative for the toolchain; do not invent alternatives.

Package manager is **pnpm** (`pnpm-lock.yaml`). The unit-test runner is **Vitest** (`vitest.config.ts` — a plain `vitest/config` `defineConfig` with `vite-tsconfig-paths`; run via `pnpm test`): co-located `*.test.ts(x)` specs, **node** by default, with DOM-dependent specs opting into happy-dom per file via a `// @vitest-environment happy-dom` docblock. Component (browser-mode), e2e, and a11y suites are not configured yet.

## Commands

- `pnpm dev` — Astro dev server. `/` serves the landing home.
- `pnpm build` — production build. `/` is the landing home; the former holding page builds at `/maintenance`.
- `pnpm preview` — serve the production build locally.
- `pnpm typecheck` — `astro check` (TS + `.astro` diagnostics).
- `pnpm test` — `vitest run`: the unit suite (co-located `*.test.ts(x)`; node + happy-dom per spec). Also gates pre-push and the CI `Unit Tests` check.
- `pnpm lint` — CI-style, no writes: `biome check` (JS/TS/CSS/JSON) + `prettier --check` (`.astro`/`.yaml`). Run before committing.
- `pnpm lint:fix` — autofix: `biome check --write` (JS/TS/CSS/JSON) + `prettier --write` (`.astro`/`.yaml`).
- `pnpm lighthouse` — local budget gate: `astro build` then `npx -y @lhci/cli autorun` (the **scoped** `@lhci/cli`, reads `lighthouserc.json`, mirrors the CI `Lighthouse` job). Append `--collect.settings.preset=desktop` for a desktop pass. Never run `npx lhci` — the unscoped `lhci` package is an unrelated typosquat.

Deploys run through the Cloudflare **Workers Builds** git integration on the Worker `adeonir`: a push to `main` runs `pnpm build` then `npx wrangler deploy`, publishing production at `adeonir.dev`. It ships as an **SSR Worker** via the `@astrojs/cloudflare` adapter — the committed `wrangler.jsonc` sets `name`, `compatibility_date`, `compatibility_flags: ["nodejs_compat"]`, the adapter `main` entry, `assets.directory: ./dist/client` (the adapter relocates the static build there from `./dist`), and a `RATE_LIMIT` `kv_namespaces` binding (`id` + `preview_id`). `wrangler` is a direct devDependency so the deploy step resolves it (transitive-only leaves its bin unlinked in the build env). Per-environment variables — including the `RESEND_API_KEY` server secret (`astro:env/server`), held in `.dev.vars` locally — live in the Cloudflare dashboard, not in the repo; `package.json` pins the package manager via `packageManager: pnpm@11.5.2` (the build env otherwise falls back to a pnpm 10.x that cannot parse the v11 `allowBuilds` syntax). `pnpm-workspace.yaml` `allowBuilds` must hold only resolved `true`/`false` values for deps present in the tree — an unresolved placeholder there hard-crashes **every** `pnpm run` via the pre-run deps check.

Formatting is split by file type: **Biome** owns JS/TS/CSS/JSON (`.astro` is excluded in `biome.json`; CSS is double-quoted via `css.formatter` with `css.parser.tailwindDirectives` enabled for the Tailwind v4 at-rules, and `**/*.css` is in `.prettierignore` so Prettier never touches it); **Prettier** owns `.astro`/`.yaml`. Tailwind class sorting follows the same split — Biome `useSortedClasses` (functions `cn`/`clsx`/`cva`/`tv`) for code, `prettier-plugin-tailwindcss` for `.astro`. Lefthook runs both on staged files pre-commit and `pnpm typecheck` pre-push; install the git hooks manually with `lefthook install` (the `prepare` auto-install script was removed).

## Planned architecture (per design-doc.md)

- **Astro app on Cloudflare Workers (workerd runtime), shipped as an SSR Worker via `@astrojs/cloudflare`.** Every content page prerenders to static HTML; the **only** on-demand surface is the contact Action endpoint (`/_actions/contact`), server-rendered by the adapter and invoked client-side from the contact island — there is no `prerender = false` page route. Read bindings/secrets via `import { env } from 'cloudflare:workers'`, get `waitUntil` from `Astro.locals.cfContext`, and the client IP from `Astro.clientAddress` (adapter v13 removed `Astro.locals.runtime`).
- **React islands** (`@astrojs/react`) for the ~4 interactive pieces only: theme toggle, contact form, language switcher, mobile nav — hydration deferred via `client:*` directives. Runtime decision recorded in `docs/adr/001-react-islands-runtime.md`.
- **Content layer** under `src/content/`: the scaffolding is wired (`src/content.config.ts` + `src/content/schemas.ts`) with a `settings` collection (site metadata via the `file()` loader). Per-section YAML copy collections (`hero`/`about`/`stack`/`header`/`footer`/`not-found`) are now built on the same scaffolding, validated by the shared `schemas.ts` (Zod). Still planned: a `projects` MDX collection (one case study per folder, colocated images).
- **Contact flow (wired):** the Action (`src/actions/index.ts`, `accept: 'form'`) runs Zod validate → honeypot (non-empty `website` ⇒ silent success-shaped discard, no email — never throws, so the fallback address never leaks to a scraper) → KV rate-limit counter (5 req / 10 min per IP, keyed on `Astro.clientAddress`; over-limit throws `TOO_MANY_REQUESTS`) → send two transactional emails via Resend (visitor's address as `reply_to` on the owner notification; non-2xx throws `INTERNAL_SERVER_ERROR`) → discard → record a non-blocking conversion count in `cfContext.waitUntil`. No database, nothing persisted or logged. The contact section lives on the home; the React island (`src/components/islands/contact-form.tsx`, `client:visible`) owns the whole client flow — per-field Zod validation via `src/hooks/use-form.ts` against the shared `src/validations/contact.ts`, submit through `actions.contact()` with no navigation, and inline success/error panels (the error state's direct fallback channel, EC-2, is the always-rendered contact list beside the form). UTM attribution is wired: the island reads `utm_source/medium/campaign` from `window.location.search` and appends the present ones to the FormData, and the Action reads them from its validated `input` — not `context.url`, which is the action endpoint and carries no page query — before the conversion capture.
- **External services:** Resend (outbound email), a hosted mailbox on `adeonir.dev` (inbound `contato@adeonir.dev`), PostHog (cookieless, privacy-first analytics — pageviews + UTM, no device storage).
- **Styling (wired):** Tailwind v4 CSS-first in `src/styles/global.css` — raw Catppuccin scales as plain `:root` vars in **oklch**, semantic roles aliased per skin (dark on `:root`, latte under `[data-theme=light]`) and exposed via `@theme inline` so a runtime skin flip re-resolves with no rebuild, a skin-neutral `--ink` for text on accent fills, plus nine `@utility text-*` type-role composites. Style against the semantic utilities (`bg-background`, `text-foreground`, `text-display`) — never hardcode hex.
- **UI primitives:** Ark UI (`@ark-ui/react`), scaffolded via the `ark-ui` MCP server. Wire every component to the dual-skin tokens; never keep a default palette. Audit against the design do/don'ts after scaffolding. Docs: https://ark-ui.com/llms.txt

## Section composition & content (implemented landing)

- **Sections are pure content.** `src/components/sections/*.astro` render only their `<section>` markup — no width, gutter, or vertical-spacing classes — so they stay portable across pages.
- **The shell owns the content column.** `base.astro`'s `<main class="wrapper flex flex-col gap-16 py-16 md:gap-24 md:py-24">` applies the `@utility wrapper` (`mx-auto w-full max-w-6xl px-6`) once; the header and footer inner containers reuse `wrapper` too. Change the column width in one place (`wrapper` in `global.css`) and header/main/footer stay aligned. Inter-section rhythm is the shell's `gap`, not per-section padding; `Divider` is a `w-full` sibling that inherits the column.
- **Pages compose sections.** `index.astro` (the home) mounts `<Hero/><Divider/><About/><Divider/><Stack/><Divider/><Contact/>` through `Layout` (with the `shell` prop).
- **Typed copy collections.** Each section reads its own collection (`hero`/`about`/`stack`/`header`/`footer`/`not-found`/`settings`) via `getEntry`, validated by shared Zod schemas in `src/content/schemas.ts` (`import { z } from 'astro/zod'`). The `file()`-loader `getEntry` returns `T | undefined` — guard before `.data`. Headline/tagline copy is a segment array whose per-segment flags drive rendering: `strong` → `text-secondary` (large text), `emphasis` → `text-emphasis` (small text) per `.claude/rules/text-highlight-segments.md`, `break` → `<br>` (controlled two-line wrap, often gated `hidden md:block`). `docs/design/copy.yaml` is the canonical prose (source of truth, authored pre-impl); the collections carry the rendering markup — **headline emphasis and breaks come from the Figma frame, not `copy.yaml`, which omits them.**
- **Icons.** `unplugin-icons` + `@iconify-json/tabler` — `import IconFolder from '~icons/tabler/folder'`, rendered statically in `.astro` (no hydration; needs `@svgr/core` + `@svgr/plugin-jsx`).
- **Verifying landing sections.** The landing is the production home — `pnpm build` compiles it to `dist/index.html`; verify there or via `pnpm dev`. Editing `content.config.ts`/`schemas.ts` needs a dev-server restart to take effect.

## Conventions (per design-doc.md §3.3)

- **Files:** `kebab-case`. **Component export:** `PascalCase` — `.tsx` components use a named export (`export function Button`); `.astro` components are the file's implicit default (`project-card.astro` → `ProjectCard`). Slugs, folders, routes lowercase.
- **Component tiers** — four directories, each with a distinct role:
  - `src/components/` — `.astro` for server-side composition; `.tsx` for stateful React reused inside islands
  - `src/components/islands/` — React hydration boundaries; used with `client:*` in templates
  - `src/components/sections/` — `.astro` files for each page section
  - `src/components/ui/` — styled primitives, no state, semantic tokens only; built on the Ark UI factory (`ark.<element>`) by default so each is polymorphic and accepts `asChild` — whether it wraps an Ark primitive or a plain element. Drop to a bare HTML element only for a trivial primitive that never needs `asChild`
  Use `/new-component` skill to scaffold any tier.
- **`src/lib/`** — shared pure helpers, no JSX (e.g. `cn` class composer). **`src/hooks/`** — shared React hooks for islands (e.g. `use-form`).
- **Imports:** `~/` alias (resolves to `src/`, per `tsconfig.json`) for any cross-directory import; reserve `./`/`../` for same-directory files. JSX is React (`jsxImportSource: react`); use `className` in `.tsx`, `class` in `.astro`.
- **Local conventions in `.claude/rules/`** are auto-loaded and enforced: kebab-case filenames, `~/` alias imports, Tailwind canonical shorthand over arbitrary values, and commit/PR-merge format. Read them before large edits.
- **Routing / i18n:** routing-based, `i18n.routing.prefixDefaultLocale = false`. Portuguese is the default and ships bare at `/`, `/work`, `/work/[slug]`, `/404`; English mirrors under `/en/...`. Locale keys are `pt`/`en` but emitted `lang`/`hreflang` are `pt-BR`/`en` (decoupled). Build localized links with `getRelativeLocaleUrl()`. No client-side language switching, no browser auto-detect.
- **Localized content:** default locale is bare (`*.yaml`, `index.mdx`); English carries an `.en` suffix (`*.en.yaml`, `index.en.mdx`). Cover/gallery images are shared across locales.
- **Quality budget:** mobile Lighthouse Performance ≥ 95, Accessibility/Best-Practices/SEO 100; LCP < 2.0s, CLS < 0.1, INP < 200ms; WCAG 2.1 AA. The performance budget is **CI-enforced on the home** by a Lighthouse CI gate (`lighthouserc.json` + the `Lighthouse` job in `ci.yml`): category scores hard-fail the audit, Core Web Vitals are advisory warnings (INP via the TBT lab proxy), and `Lighthouse` is a required check on `main`. The axe/WCAG element gate remains the design's plan, not yet wired.

## Design system essentials (per DESIGN.md)

- **Two skins of one identity:** dark is default (`mocha`/Catppuccin scale), light is the counterpart (`latte` scale). Steps are position-numbered so the same step is the same role in both skins.
- **Two accents, two jobs:** `primary` (blue — `stream` dark / `ocean` light) **acts** — it owns every interactive cue (CTA, link, focus ring, hover). `secondary` (pink — `azalea` dark / `hibiscus` light) only **points** — static emphasis on text, never interactive.
- **Hard don'ts:** no gradients, glows, or a third accent; pink never acts (no pink buttons/links/focus); separate surfaces with a tone drop + hairline `border` before any shadow; never pure `#000`/`#fff`.
- **Type:** Geist for everything (display→caption), Fira Code only for genuinely technical content.

- `src/pages/maintenance.astro` / `public/logo.svg` — standby maintenance page at `/maintenance` (`title="Manutenção"`, `noindex`); centered logo through the base `Layout`, semantic tokens only.
- `src/pages/404.astro` — global `noindex` not-found page; renders the `notFound` copy collection (eyebrow, oversized `404` mark, headline with `strong` accent, body, back-home action) through the base `Layout` in the home section composition. The static-assets Worker serves it with a 404 status on unmatched routes.
- `src/pages/styleguide.astro` — `noindex` design-token styleguide at `/styleguide` (hidden from crawl via `noIndexRoutes`); renders `sections/styleguide.astro` twice side by side (dark + light skin) in its own HTML shell — not the base `Layout` — importing `global.css` directly.
- `src/layouts/base.astro` (default import `Layout`) — the shared document shell: `<html lang>` + `<body>` token classes, head built with `astro-seo`'s `<SEO>` (page-first title template `{title} | {siteName}`, Open Graph, `twitter:card=summary_large_image`, absolute canonical/og:image from `Astro.site`), hand-rolled favicon/apple-touch/manifest links, and `<Analytics />`. Props: required `title`, optional `description`/`image`/`noindex`. Adopt this for every new page.
- `src/content.config.ts` + `src/content/schemas.ts` + `src/content/settings.yaml` — content-layer scaffolding; the `settings` collection (`file()` loader) holds site metadata (`siteName`, `description`, `ogImage`, `locale`), read via `getEntry('settings', 'metadata')`. The per-section copy work extends these files — do not recreate them.
- `src/components/analytics.astro` — config-gated cookieless PostHog `<script is:inline>`, emitted only when `POSTHOG_KEY` is set (`astro:env/client`; `POSTHOG_HOST` defaults to the first-party reverse proxy `https://t.adeonir.dev`). The official array-stub snippet async-loads the client (`/static/array.js` from the derived assets host) and calls `posthog.init` hardened cookieless (`cookieless_mode: 'always'`, memory persistence + `disable_persistence`, autocapture/session-recording/surveys off, `respect_dnt`, `advanced_disable_flags`); pageview-on-load stays on (one UTM-attributed `$pageview` per load). Inert (no script, no request) when the key is unset. The key lives in env (gitignored `.env` locally + Cloudflare dashboard env in prod), never in source.
- `astro.config.mjs` — sets `site` (`https://adeonir.dev`), `adapter: cloudflare()` (enabling on-demand rendering for the contact Action endpoint), the `@astrojs/sitemap` and `astro-robots-txt` integrations (both fed by a shared `noIndexRoutes` list — `/styleguide` + `/maintenance` — so the sitemap `filter` and the robots `disallow` stay in sync), and the `env.schema` declaring `RESEND_API_KEY` (server secret) plus the two public client PostHog vars (`POSTHOG_KEY` optional — gates emission; `POSTHOG_HOST` defaults to `https://t.adeonir.dev`, the first-party reverse proxy).
- `src/actions/index.ts` — the contact Action (`accept: 'form'`): validate → honeypot silent-discard → KV rate-limit → send → discard → `cfContext.waitUntil` conversion capture; throws typed `ActionError`s (`TOO_MANY_REQUESTS`, `INTERNAL_SERVER_ERROR`).
- `src/services/email.ts` / `rate-limit.ts` / `analytics.ts` — Resend send (raw `fetch` + `@react-email/render`, copy from the `emails` collection), the KV read-modify-write rate-limit counter (`env.RATE_LIMIT`, key `rl:<ip>`, `expirationTtl: 600`), and the PostHog conversion capture (direct fetch, synthetic `distinct_id`, takes a UTM tag map from the Action `input` — the action endpoint URL has no page query — swallows failures, gated on `POSTHOG_KEY`).
- `src/emails/confirmation.tsx` / `notification.tsx` — react-email templates, render-only, fed `copy` + `replyTo` props from the `emails` collection.
- `src/validations/contact.ts` — Zod input schema; imports the canonical `zod` package (not `astro/zod`) because the schema is shared with the client island — the `createContactSchema(messages)` factory parameterizes validation copy and is `safeParse`d in the browser by `use-form`, so it ships to the client bundle and must not couple to Astro's internal re-export (server-only content schemas in `src/content/schemas.ts` still use `astro/zod`). It also declares the optional `utm_source/medium/campaign` passthrough fields and exports `UTM_KEYS`, shared by the island (reads them off the URL) and the analytics capture. `website` is the optional honeypot, checked in the handler (not at validation, so the bot reaches a silent discard).
- `src/components/islands/contact-form.tsx` + `src/hooks/use-form.ts` — the contact island and its form hook: client-side per-field Zod validation, submit via `actions.contact()` with no navigation, inline success/error panels, UTM forwarding from `window.location.search`, and focus-to-first-invalid on submit so assistive tech announces the error. `src/components/ui/field.tsx` is the Ark `Field` primitive extended with `invalid`/`error` props (destructive-token border + `Field.ErrorText`).
- `wrangler.jsonc` — SSR Worker config: adapter `main`, `compatibility_flags: ["nodejs_compat"]`, `assets.directory: ./dist/client`, and the `RATE_LIMIT` KV binding (`id` + `preview_id`).
- `worker-configuration.d.ts` — generated by `wrangler types`; committed so CI `astro check` resolves `env.RATE_LIMIT` (the adapter does not emit binding types).
- `.github/workflows/ci.yml` + `lighthouserc.json` — the pull-request gate. `ci.yml` runs a `quality` matrix (lint/typecheck/build) plus a `Lighthouse` job that builds the site and audits the home with `treosh/lighthouse-ci-action`. `lighthouserc.json` restricts the audit to the home (`staticDistDir: ./dist/client` — repointed after the adapter relocated the static output — + `url: ["http://localhost/"]`, disabling HTML auto-discovery so the noindex pages are never measured), runs 3× with median aggregation, hard-gates the category budget (`error`), and warns on Core Web Vitals (`warn`). All five checks (Build, Lint, Typecheck, Workers Builds, Lighthouse) are required on the `main` ruleset. Reproduce the gate locally with `pnpm lighthouse` (`@lhci/cli autorun` against the same config) — there is no local lighthouse dependency.
- generated `robots.txt` + sitemap — both produced at build: `astro-robots-txt` emits `robots.txt` (a `Disallow` per shared `noIndexRoutes`, pointing at `sitemap-index.xml`), `@astrojs/sitemap` emits the sitemap. There is no static `public/robots.txt`. Owner icon/OG assets (`favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192/512/maskable-512.png`, `og-image.png`, `site.webmanifest`) live in `public/`.
- `src/styles/global.css` — the wired design layer: `@import "tailwindcss"` + self-hosted Geist/Fira Code variable fonts (`@fontsource-variable/*`, same-origin), raw oklch scales, dual-skin semantic roles via `@theme inline` (including the `destructive` error role), `@theme` fonts + `--breakpoint-xs`, the `text-*` type utilities, and the `wrapper` page-column utility. Import it wherever styles are needed.
